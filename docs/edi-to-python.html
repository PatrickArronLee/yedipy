The translation is not a black box

EDI becomes a Python object.

YediPy keeps the original X12 intact, then gives Python a structured, typed view of the transaction. The interchange remains traceable all the way through.

Nothing gets quietly erased.

Source bytes, segment order, element positions, unknown segments, and safe diagnostics stay available alongside the typed result.

Why it matters

Useful structure without losing the evidence.

01

Lossless first

The raw interchange is still there when a downstream decision needs provenance.

02

Typed where known

Supported 270 hierarchy becomes named Python fields instead of positional strings.

03

Safe when broken

Diagnostics expose structural locations, not member data or raw field values.

The objects you receive

From transport syntax to a navigable model.

Start with a generic interchange, narrow to an ST/SE transaction, and then ask for a typed implementation-specific model.

X12Interchange Source bytes, delimiters, ordered segments, and transactions.
RawTransaction One lossless ST/SE slice with its control information.
Transaction270 A typed eligibility inquiry rooted in its original transaction.
SubscriberLevel Subscriber identity, inquiries, dependents, and raw segment references.

YediPy does not pretend EDI is easy. It makes it inspectable, testable, and usable in Python without severing the connection to the original transaction.
