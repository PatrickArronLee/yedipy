# X12 270 Support

YediPy currently supports the structural hierarchy of the HIPAA X12 270 Eligibility, Coverage, or Benefit Inquiry implementation convention `005010X279A1`.

## Parsed Structure

| Loop | Model | Key segments |
| --- | --- | --- |
| 2000A / 2100A | `InformationSourceLevel` | `HL`, `NM1` |
| 2000B / 2100B | `InformationReceiverLevel` | `HL`, `NM1` |
| 2000C / 2100C / 2110C | `SubscriberLevel` | `HL`, `NM1`, `EQ` |
| 2000D / 2100D / 2110D | `DependentLevel` | `HL`, `NM1`, `EQ` |

The parser validates the `ST` transaction identifier and implementation version, exactly one `BHT`, `HL` parent relationships, required `NM1` records for supported hierarchy levels, and nonempty `EQ01` service type codes when `EQ` is present.

## Example

```python
from yedipy.x12.transactions.v5010 import parse_270

result = parse_270(raw_transaction, delimiters)
result.errors
result.transaction.information_sources[0].receivers[0].subscribers[0]
```

`EQ01` is split using the interchange repetition separator. Raw segments remain available through `raw_segment`, `raw_segments`, and `raw_transaction` fields.

## Current Limits

- The parser is structural; it does not perform payer-specific eligibility workflow logic.
- It does not validate terminology or external code sets.
- It does not transform 270 data to FHIR.
- It does not serialize typed models back to normalized X12 yet.
